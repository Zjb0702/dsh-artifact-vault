# 产物管家 · Artifact Vault

把「同一个工作目录里堆满了各会话产物」这件事变成可管理的清单：**按会话归属、按版本排序、可视化状态、可回收的磁盘管理**；同时让每个会话在自己的专属文件夹里工作，工具脚本和交付产物分开存放。

没有它时，DSH 默认工作区是一个扁平的大文件夹，你只能靠文件名猜哪个文件是哪个会话写的。装上它之后，每个会话都有一个 `sessions/<日期>-<会话ID>/` 工作区，产物能追到产出它的会话，同一份文档的 v1/v2/终稿会自动排成一列。

## 在哪里打开

打开 **设置**（左下角齿轮）→ 左侧导航里的 **「产物管家」** 一节，页内含 会话 / 未归类 / 存储 / 重复 四个标签页。

## 它怎么知道哪个文件属于哪个会话

不靠文件名，也不靠你手动登记。插件读取每个会话自己的事件日志（`tool/call` 里记录的写入路径），据此还原「这个会话写过哪些文件」。因此：

- 历史会话同样能被索引，不需要事先安装插件；
- 只会记录到**确实被工具写过的路径**，包括 `write` / `edit` / `apply_patch` 以及 `present` 宣告的文件；
- 子代理（subagent）产出的文件会合并回它所属的父会话，因为它们的工作本来就是一个任务的一部分；
- 会话名字取会话自己的标题（`session/title` 记录），刚建还没生成标题时退回到第一条用户消息，不再显示「未命名会话」。

每个会话的日志只会被重新读取一次（用持久化修订号判断是否有变化），扫描是增量的。

## 会话工作区

启用后，每个会话在项目目录下拥有一个专属文件夹：

```
<项目目录>/sessions/20261118-a1b2c3d4/
├── tools/      运行期写的临时脚本、探测代码、一次性命令
└── artifacts/  交付产物：文档、表格、演示、图片、数据、压缩包
```

- 文件夹名 = 会话创建日期 + 由会话 ID 派生的 8 位短 ID（`a1b2c3d4`，只含字母和数字，避开 `0/o/1/l/i` 便于口述与输入）。同一个会话永远得到同一个短 ID，所以你能从 ID 反查文件夹，也能从文件夹反查会话。
- 面板里每个会话都显示这个短 ID 和文件夹路径，可一键复制路径。
- 插件会向模型注入一条工作区约定（`tools/` 放脚本、`artifacts/` 放产物、不在公共目录留散落文件），新会话自动遵守；已有会话可以在「存储」页点「为全部会话启用工作区」，或在会话详情页单独启用。
- 启用会把该会话的工作目录切换到它的文件夹；项目根目录仍然保留文件工具写权限，因此共享文件的读写不受影响（Windows 上进程类写入仍受沙箱边界约束，这是 DSH 的安全模型）。

## 四个标签页

| 标签 | 作用 |
| --- | --- |
| **会话** | 每个会话一行：中文标题、短 ID、产物数、占用大小、最后活动时间。点开看详情：工作区文件夹、工具/产物/散落三个分区的数量与占用、按「目录 + 去掉版本后缀的文件名 + 扩展名」分组的版本列表（v1、v2 …）。 |
| **未归类** | 扫描工作区里的文件，把**没有任何会话记录**的文件按顶层目录分组——这正是过去那堆「不知道谁写的」文件。每个文件夹一张带边框的方框，默认**收起**；点「删除文件夹」整夹一次性回收，或展开后勾选若干行「删除所选」批量回收（`/trash-many`，单个失败不影响其余）。 |
| **存储** | 顶部是清理优先级卡片（① 工具脚本 → ② 产物 → ③ 散落文件，逐级清理）、工作区启用按钮、按会话排名的占用条形图，以及回收站：还原、彻底删除、清空。 |
| **重复** | 按内容哈希找重复文件，显示每个文件属于哪些会话，以及重复占用了多少空间。 |

## 版本分组与状态标记

同一目录下 `方案 v1.docx` / `方案 v2.docx` / `方案-最终版.docx` 会归为同一组，按首次写入时间编号。每个版本带有状态标记：

- **已标注**：会话里用 `present` 工具正式交付过（或你手动标注过），说明这是有意义的成果而不是中间文件；
- **推断**：路径来自命令行重定向、`cp` 之类的低置信度线索，可能是中间产物；
- **后续修改**：文件在会话结束之后又被改过（可能是你手动改的，也可能是别的会话）；
- **已缺失**：记录里的文件现在不存在了（被删除或移动）。

## 管理动作

- **复制路径**、**复制文件夹路径**、**下载**（浏览器直接取回文件）；
- **回收**：移入插件自己的回收站（清单在 `<DSH_HOME>/artifact-vault/index.json`，**文件字节放在源文件所在盘的** `.dsh-artifact-vault-trash/<id>/` 里），原位置立刻消失，但可以还原。放在同盘是为了让移动只是一次瞬间改名——跨盘复制一个大文件（比如 8 GB 的镜像）在 C 盘快满时会直接 `ENOSPC` 失败；
- **未归类整夹删除 / 批量删除**：一个文件夹里 100+ 个文件时不必逐条点，直接「删除文件夹」整体回收，或勾选后批量回收；
- **回收站整体还原**：文件夹被回收后作为一个条目存在，还原时整夹回到原位；产物分组默认**收起**，点标题行才展开版本列表；
- **按分区清理**：在会话详情页分别清理 `tools/`（工具脚本）、`artifacts/`（产物）、散落文件；在「存储」页可对全部会话逐级清理；
- **回收站**：独立清单接口 `GET /trash-list`，按时间 / 修改时间 / 大小 / 名称排序，查看每个回收项的原路径与同盘暂存位置，还原 / 彻底删除 / 清空均可用；
- **还原 / 彻底删除 / 清空回收站**；
- **标注**：给某个版本起一个可读的名字，方便下次一眼认出「客户最终版」；
- **扫描更新**：把新的会话与新的写入纳入索引；**刷新尺寸**：重新统计文件大小；
- **排序**：会话列表、会话占用、产物版本、回收站都支持按大小 / 修改时间 / 名称 / 会话占用排序并切换升降序；
- **C 盘占用分析**：存储页底部展示 `~/.dsh` 各分类占用，列出**可安全释放**的计划（已删除会话的日志、可重下/可重建的插件缓存），清理前显示可释放空间和影响范围，勾选后确认执行，绝不碰工作区产物、工具脚本和仍在使用的会话日志。

清理顺序就是用户要的优先级：**先工具脚本，再产物**。清理只移动文件，**不会删除会话记忆**（会话记录本身）；只有你在 DSH 里删除了整个会话，下次扫描发现该会话既不在列表里、日志也不存在时，它的整个工作区文件夹才会被整体移入回收站（带「会话已删除」标记），可以还原或彻底清空。

## 给模型用的工具

插件注册了一个 `artifact_declare` 工具：模型在交付产物时可以用它登记

```json
{ "path": "artifacts/方案.docx", "label": "客户最终版", "note": "含报价" }
```

被登记的产物会直接以「已标注」出现在对应会话下，不依赖路径猜测。

## 配置项

这些键可以写在 bundle 的 patch 行 `config` 里：

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `sessionFolders` | `true` | 启用「每会话一个工作区文件夹」；关掉则回到单一扁平目录 |
| `sessionsDirName` | `sessions` | 工作区父目录名 |
| `toolsDirName` | `tools` | 工具脚本子目录名 |
| `artifactsDirName` | `artifacts` | 产物子目录名 |
| `sessionFolderRoot` | `""` | 指定工作区创建位置；留空用会话原工作目录 |
| `autoAdoptSessions` | `true` | 新会话自动切换进自己的工作区 |
| `adoptSessionsCreatedAfter` | `0` | 自动接管的时间下限（毫秒时间戳）；`0` 表示用插件本次启动时间，即只自动接管启动之后新建的会话，旧会话在面板里手动启用 |
| `skipSessionIds` | `[]` | 不接管工作区的会话 ID |
| `keepBaseWritable` | `true` | 切换工作区后仍保留项目根目录的写权限 |
| `promptRule` | `true` | 向模型注入 `tools/` `artifacts/` 约定 |
| `trashOnSourceDrive` | `true` | 回收站字节放在源文件所在盘（瞬间改名、不占 home 盘空间）；`false` 则退回旧行为放到 `<DSH_HOME>/artifact-vault/trash/` |
| `trashDirName` | `.dsh-artifact-vault-trash` | 同盘暂存目录名（位于每个扫描根目录下） |
| `autoScan` | `true` | 后台定时增量索引会话 |
| `scanIntervalMinutes` | `10` | 定时扫描间隔（分钟） |
| `maxScanPerBatch` | `6` | 每次扫描最多读取的会话数 |
| `includeSubagents` | `true` | 把子代理产物合并到父会话 |
| `roots` | `[]` | 额外的扫描根目录；留空表示使用各会话的工作目录 |
| `maxUntrackedDepth` | `4` | 「未归类」扫描的目录深度 |
| `maxUntrackedFiles` | `6000` | 「未归类」扫描的文件上限 |
| `ignoreDirs` | `node_modules`、`.git`、`.venv` 等 | 「未归类」不再往下走的目录名（依赖与缓存目录；`out`/`dist` 这类产物目录不会被跳过，除非你自己加进去） |

索引与回收站数据保存在 `<DSH_HOME>/artifact-vault/` 下（默认 `~/.dsh/artifact-vault/`），是一个纯 JSON 文件，删掉即可重置。

## 自测

仓库内的三份无依赖测试可以直接跑（Node 22 即可，不需要装 DSH）：

```bash
node test/logic.mjs        # 文件名归一、版本分组、工具调用 → 路径抽取、短 ID 与分区判定
node test/client-smoke.mjs # 加载器握手、inject 声明、settings.section 注册、样式注入
node test/host-smoke.mjs   # 临时目录上的扫描、标题、工作区创建与接管、按分区清理、会话删除、回收站、去重、持久化
node test/features-smoke.mjs # 文件夹回收、回收站排序与还原、C 盘占用分析与安全清理
```

## DSH 为什么装在 D 盘、C 盘却越来越满

应用主体在 D 盘，但 **DSH 的数据目录 `~/.dsh` 在 C 盘**（这台机器是 `C:\Users\Administrator\.dsh`）。随着会话与插件增多，以下内容都在 C 盘累积：

| 来源 | 实测（本机） | 是否可清理 |
| --- | --- | --- |
| `~/.dsh/plugins/rea-bundle/` | 2.8 GB（其中 `cache/` 838 MB 是可重下的 zip/jar） | ✅ 缓存可清；vendor 是运行依赖，不动 |
| `~/.dsh/sessions/<项目>/<会话ID>/session.v4.jsonl.zstd` | 46 MB（24 个文件，单会话最大 16 MB） | 仅"会话已不存在"的日志可清；活会话绝不动 |
| `~/.dsh/storages/session_projcache/` | 6.7 MB 派生缓存 | 可由日志重建，但收益小 |
| `~/.dsh/profiles/desktop/node_modules/` | 370 MB 已装插件 | 删除会导致插件失效，不动 |

面板的「C 盘占用分析」会实时列出这些分类与**可安全释放**的清单；勾选后显示影响范围并二次确认，清理只针对清单内路径（已删除会话日志 + 可重下缓存），不会删除工作区产物、工具脚本、活会话记忆。它**不撤销**：dsh-session-manager 删除会话时已硬删其日志，本功能只回收那些"已经没人要"的残留缓存。

> 安全边界：`session-manager v0.7.8` 删除会话时只删 `~/.dsh/sessions/<项目>/<会话ID>/` 的日志目录（rm -rf），不动工作区文件夹、不碰 `~/.dsh/artifact-vault`。因此工作区里的 `tools/`、`artifacts/` 永远由产物管家按会话独立管理，与 C 盘清理互不干扰。

## 支持平台

DSH 能跑的地方它就能跑：**macOS、Windows、Linux**。插件是纯 Node、只用内置模块，没有需要按平台重编译的原生模块。

- **路径处理区分平台**：`pathKey` 只在 Windows 折叠大小写，其它系统保留原样；所有比较都走 `node:path`，不用字符串拼接。
- **跨卷回收在三个平台都成立**：同卷移动是一次瞬时的 `rename`；跨卷会拿到 `EXDEV` 并回退到复制+删除（`trashOnSourceDrive` 正是为此存在）。
- **额外的可写根目录在 macOS 上比 Windows 更完整**：macOS 的 Seatbelt profile 会把 `additionalWritableRoots` 展开成 `(allow file-write* (subpath …))`，受控进程也能写项目根；Windows 上只有 harness 文件工具享受该授权，进程权限不变。
- **文件系统簿记被过滤**：`.DS_Store`、`Thumbs.db`、`desktop.ini`、`.Spotlight-V100`、`.fseventsd`、`$RECYCLE.BIN` 等不会出现在「未归类」里。

两个需要知道的平台差异：

- **大小写不敏感文件系统**：macOS 默认的 APFS 不区分大小写，而 `pathKey` 在非 Windows 平台保留大小写，因此 `Report.md` 与 `report.md` 会被当作两个路径（磁盘上其实是同一个文件）。Windows 不受影响。若依赖版本分组，请统一命名。
- **未归类扫描跳过符号链接**：通过符号链接到达的工作区（例如 macOS 上 `/var` 与 `/private/var`）不会继续深入；已归属的会话不受影响，因为它们的路径来自会话日志。

测试套件是跨平台的：`node test/logic.mjs` 用按平台生成的基础路径，并针对 `pathKey` 的文档化差异做断言，三种系统都能通过。

## 已知边界

- 只能发现**通过工具调用写入**的文件：你在终端里手敲命令生成、或用别的编辑器写的文件不会自动归属到某个会话，它们会出现在「未归类」里。
- 归属是「这个会话碰过这个路径」，不是「这个会话原创了这个文件」；多个会话改同一个文件时，它们都会出现在该文件的来源里。
- 会话日志必须可读（持久化会话或仍在内存中的会话）；日志损坏的会话会在列表里标出「读取失败」。
- 「会话已被删除」的判定依据是「会话列表里没有 + 日志文件也不存在」，这是 DSH 没有删除事件时的可达近似；工作区被移入回收站而不是直接删除，所以判断失误也能还原。
- 「未归类」按目录聚合而不是按文件内容聚类，它回答的是「哪些目录没人认领」。
- 所有接口只监听本机回环地址，浏览器端与宿主端在同源下通信。
